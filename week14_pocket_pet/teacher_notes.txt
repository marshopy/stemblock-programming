── OVERVIEW ────────────────────────────────────────────────

  We have new students, so this class reviews EVERY Level 2
  concept from the ground up, in the same style as Weeks 1-7
  (Vapor Trail slides, console programs, "what's the print
  value?" challenges like the Week 5 review).

  Deck:  week14_Level2_Review.pptx  (35 slides, speaker notes
         on every slide, answer key on the last slide)

  No tkinter this week: Pocket Pet is a text game in the
  Thonny Shell, so new students only need print() and input().

  Week 15 (Boba Order Tracker) builds on this with the
  Week 12/13 tkinter template, focused on lists and dictionaries.

── HOW TO RUN PART 1 ───────────────────────────────────────

  Every concept slide has EXAMPLES on the left and a CHALLENGE
  on the right.

       answer from the notes / Answer Key slide.

── HOW TO RUN PART 2 (CODE-ALONG) ──────────────────────────

  Students open  pocket_pet_starter.py  — it only has the step
  headings, so everyone types the code themselves.

  For each step:  explain the idea (30 sec) → type it together
  on the projector → everyone presses F5.  No red error = success.

  Steps 3-6 have a "TEST IT" box: two or three lines to add at
  the very bottom of the file to try the new method.  Delete
  those test lines at Step 8.

  Step 9 is split across two slides (skeleton first, then the
  if / elif / else) so the code stays big enough to read.


── STEP-BY-STEP: COMMON MISTAKES ──────────────────────────

  STEP 1  The data
    • Missing comma between dictionary items → SyntaxError
    • Forgetting the closing ] on TRICKS (it's split over 2 lines)

  STEP 2  The Pet class
    • _init_ with ONE underscore each side — it needs TWO
    • Forgetting  self  as the first parameter
    • hunger = 5  instead of  self.hunger = 5
      (the pet "forgets" it straight away)

  STEP 3  Show status   (first chance to TEST)
    • def show_status is not indented under the class
      → the test says  'Pet' object has no attribute 'show_status'
    • Forgetting the  f  before the quotes → shows {self.name} literally

  STEP 4  Feed
    • FOODS(food) with round brackets → 'dict' object is not callable
    • No  if food in FOODS  check → KeyError: 'rocks'

  STEP 5  Play & sleep
    • Test: pet.play() three times → 5 → 3 → 1, the third says
      "too tired".  Ask why  >= 2  and not  > 2.

  STEP 6  Learn a trick
    • self.tricks.append(trick) outside the else → duplicates
    • Some calls say "Already knows" — that's random.choice
      picking the same trick twice, not a bug!

  STEP 7  End of the day
    • is_ok() must RETURN the comparison, not print it

  STEP 8  Menu & making our pet
    • These lines are NOT indented (outside the class)
    • Delete the test lines from Steps 3-6 first

  STEP 9  The game loop
    • choice == 1 (a number) — input() gives TEXT, use "1"
    • pet.end_of_day() indented inside the while → the day ends
      after every action.  It lines up with  while.
    • The if / elif / else must be indented 8 spaces (inside while)
    • The typo trick: else adds 1, then the line after subtracts 1
      → a wrong key doesn't use up a turn

  STEP 10  Game over
    • These lines are at the left edge, after the for loop
    • day still holds the last day we reached (after the loop)


── TESTING THE FINISHED GAME ───────────────────────────────

  • Name: Mochi → play a normal game → should reach Day 5
  • Type 9 at the menu → "Please type 1, 2, 3 or 4", same day
  • Feed "rocks" → pet says no
  • Only choose 4 (sleep) every time → hunger rises, happiness
    drops → "Oh no! ... is not okay" by the last day
  • A good run (feed, play, tricks, sleep when tired) → ⭐⭐⭐
